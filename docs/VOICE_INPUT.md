# 语音输入

交互参考手机聊天 App 的听写流程：点击输入框旁的麦克风 → 录音并实时转写 → 结束 → 编辑 → 使用文字 → 回到草稿后手动发送。本项目没有获取或复用 ChatGPT iPhone App 的私有界面或听写实现。

## 行为

- 点击麦克风打开语音页，首次请求 iOS 麦克风与语音识别授权。
- 录音中显示来自实际音频采样的音量波形、计时和识别文字。
- “结束录音”会停止采集，等待识别器返回最终文字；超时保留当前已有转写。
- 一段最多 55 秒，结束后可编辑，或“继续录音”追加新的一段；部分识别结果会替换当前段，避免重复堆叠。
- “使用文字”只追加到当前输入框，保留原有草稿。用户仍需点击发送按钮。
- “取消”不改原有输入框，不发送任何消息。
- 后台、来电中断、音频输入设备断开时停止录音并保留已识别文字；离开语音页面时释放麦克风。
- 中文普通话、英语及其他常用中文区域选项仅在 iOS 列出支持时显示。

## 识别来源与权限

使用 Apple `Speech` 与 `AVAudioEngine`。设备支持该语言的设备端识别时设置 `requiresOnDeviceRecognition = true`；否则允许 iOS 使用 Apple 网络语音服务。界面显示识别来源，Info.plist 包含麦克风和语音识别的用途说明。

不能保证所有设备、语言、区域或离线环境均可用。设备端能力标记不等同于语言模型已准备好；缺失资源或服务失败时保留文字、显示错误，并允许重试或切换语言。未自动绕过系统权限，也没有新增 OpenAI API 密钥配置。

本实现不保存录音文件，不把音频上传给 Ubuntu / Codex。最终文字仅在用户点击发送时经过既有 SSH 消息通道；当 iOS 使用联网识别时，音频可能由 Apple 服务处理。

## 验证边界

新增 8 项可注入假引擎的 XCTest，覆盖实时部分结果、追加、取消/迟到回调、权限错误、背景中断、授权等待期间取消、停止与最终结果竞态及草稿合并。当前 Linux 环境无法运行 XCTest 或真实 iOS 麦克风识别，因此没有声称语音已实测通过。

在 Mac 执行 `bash scripts/check-mac.sh` 进行构建与测试，随后在真机检查麦克风、系统弹窗、中文识别、网络/离线条件、旋转及中断情形。模拟器的录音和语音服务行为不能完全代表真机。
